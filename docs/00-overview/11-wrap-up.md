## 12. 理解度チェック（3分）

解答を見ずに答えられるか確認してください。答えられない項目があれば、該当章に戻ってください。

### 12-1. 設問

1. LLM API を直接呼ぶことと、エージェントを使うことの違いは何ですか。
2. 「ツールを実行する」のは LLM とアプリケーションのどちらですか。
3. Agent と Workflow はどう使い分けますか。判断基準を1つ挙げてください。
4. ツールが呼ばれない・間違ったツールが呼ばれるとき、まず疑うべき箇所はどこですか。
5. `model: 'openai/gpt-5.6-luna'` のように文字列でモデルを指定できる仕組みを何と呼びますか。
6. Memory を有効にするために、Memory 以外に必ず必要な設定は何ですか。
7. ワークフローの途中で人間の承認を挟みたいとき、使う仕組みの名前は何ですか。
8. Mastra Studio でできることを2つ挙げてください。
9. Scorer（Evals）は何のためにありますか。
10. ライセンスや課金の面で注意が必要なフレームワークを2つ挙げ、それぞれ何に注意すべきか説明してください。

### 12-2. 解答

1. LLM API の直接呼び出しは「入力に対して1回応答を返す」だけです。エージェントは LLM に道具を持たせ、**次に何をするかを LLM 自身に決めさせながら複数回のやり取りを繰り返します**（1章）。
2. **アプリケーション側**です。LLM は「このツールをこの引数で呼んでほしい」と要求するだけで、実行はしません（1-1）。
3. **手順が事前に決まっていなければ Agent、決まっている多段処理は Workflow** です。ほかに「人間の承認を挟みたい」「失敗箇所を特定したい」「出力の再現性を重視する」なら Workflow（6-4）。
4. ツールの **`description`** です。LLM はこの説明文だけを頼りに使うかどうかを判断します（5-1）。
5. **Model Router** です。プロバイダを `import` せずに文字列だけで切り替えられます（4-1）。
6. **Storage**（保存先）です。ローカルでは LibSQL のファイルを使います（7-3）。
7. **suspend / resume** です。中断中の状態はスナップショットとして保存されます（6-3）。
8. エージェントとの対話 / トレース確認（プロンプト全文・ツールの引数・トークン消費・所要時間）/ ワークフローのグラフ可視化 / `inputSchema` からの入力フォーム自動生成 のうち2つ（8-1）。
9. LLM の出力は毎回変わるため、**変更のたびに品質が上がったか下がったかを数値で測る**ためです。CI に組み込めます（8-3）。
10. **LangGraph** — 本体は MIT ですが、**サーバーランタイム `langgraph-api` は Elastic License 2.0** で、本番運用には商用ライセンスが必要です。**Dify** — Apache 2.0 ベースですが追加条件があり、**マルチテナント運用**（Dify を土台にした外部向け SaaS）には商用ライセンスが必要です。ほかに **Strands Agents** は SDK 自体は Apache 2.0 で無償ですが、長期記憶などを担う Amazon Bedrock AgentCore は AWS の有償サービスです（10-1）。
