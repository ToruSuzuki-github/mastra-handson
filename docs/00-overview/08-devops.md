# 8. 開発・運用を支える仕組み（5分）

## 8-1. Mastra Studio

`npm run dev` で開発サーバーを起動すると、ブラウザから使えるローカル GUI が立ち上がります（既定はポート 4111）。

| できること | 内容 |
|---|---|
| エージェントとの対話 | UI を自作しなくても、その場で挙動を試せる |
| トレースの確認 | 送られたプロンプト全文、呼ばれたツールと引数、トークン消費、各処理の所要時間 |
| ワークフローの可視化 | ステップのグラフ表示。どこまで進んだか、どこで止まったかが見える |
| 入力フォームの自動生成 | `inputSchema` から実行用フォームが自動で作られる |
| 過去トレースの再評価 | 記録済みのトレースに対して採点（Scorer）を後から実行できる |

**Studio があることが、Mastra の開発体験の中心です。** ハンズオンでも Day1 Step1 から使い続けます。

## 8-2. Server — そのまま HTTP API になる

`Mastra` インスタンスに登録したエージェントとワークフローは、自動的に HTTP エンドポイントとして公開されます。
`curl` からも、フロントエンドのクライアント SDK からも呼べます。Next.js・Express・Hono などに組み込む形でも、単独サーバーとして動かす形でも構いません。

## 8-3. 可観測性と品質評価

| 仕組み | 答える問い | 内容 |
|---|---|---|
| **Traces** | この回答はなぜこうなった？ | 1回の実行で何が起きたかの記録（プロンプト全文・ツール引数・所要時間・トークン）。OpenTelemetry や Datadog 等へ送ることもできる |
| **Metrics** | 全体で何回・どれくらい速く・いくら？ | 実行回数・処理時間（p50 / p95）・トークン・推定コストの**集計**。保存には分析用のデータベース（開発では DuckDB）が要る |
| **Logs** | 何が出力された？ | Mastra とアプリのログ。トレース ID で1回の実行と結びつく |
| **Feedback** | 人はどう評価した？ | 👍👎・点数・コメントなど、**人の評価**をトレースやスパンに紐づけて保存する |
| **Evals / Scorers** | 出力は基準を満たした？ | 出力を 0〜1 の数値で自動採点する。モデルによる採点・ルールベース・統計的手法がある |
| **Datasets / Experiments** | 変えたら良くなった？ | 評価用のデータセットを作り、変更前後を比較実験する |

使い分けは「**Metrics で異常に気づく → Traces で原因の1回を開く → Scorers で品質を数値にする → Experiments で直した結果を確かめる**」の順です。
Traces は出発点で、メトリクス・ログ・点数・Feedback はいずれもトレース ID で1回の実行に結びつきます。

採点はエージェント定義に組み込めます。`sampling` で全実行の一部だけを採点し、コストを抑えることもできます。

```ts
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt';

// Agent の定義に足す
scorers: {
  relevancy: {
    scorer: createAnswerRelevancyScorer({ model: 'openai/gpt-5.6-luna' }),
    sampling: { type: 'ratio', rate: 0.5 },   // 50% だけ採点
  },
},
```

> 💡 **なぜ評価が要るのか**: プロンプトを直すと、直した箇所は良くなっても別の箇所が悪化することがあります。LLM の出力は毎回変わるため、目視だけでは良し悪しを判断できません。Scorer は CI に組み込んで、変更のたびに自動で回せます。

> 手を動かして試すには、Traces と Metrics は [Day2 Step 10](../03-handson/day2/10-observability.md)、Scorers・Datasets・Experiments は [Day2 Step 11（評価）](../03-handson/day2/11-evals.md)。Step 11 では自作の Scorer、評価用 Dataset、変更前後の Experiment、CI 用スクリプトまで作ります。

## 8-4. デプロイ

ビルドすると `.mastra/` 配下に成果物が出力されます。マネージドの Mastra Cloud のほか、各種サーバーレス環境やコンテナ環境へデプロイできます。
